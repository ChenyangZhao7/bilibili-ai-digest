# 已知问题与边界

这份文档记录**外部依赖导致的问题**、我们怎么兜底、以及明确不处理的情况。改代码前先读这里，避免把外部故障当成自己的 bug 去修。

## 1. B站 AI 字幕接口会返回别的视频的字幕（严重，B站侧故障）

**症状**：报告内容和视频标题/画面完全无关。例如「毕业 2 年后的收入差距」的报告在讲 iPhone 16。

**原因**：`api.bilibili.com/x/player/v2` 返回的 `subtitle_url` 在短时间内会指向**不同的字幕文件**。实测同一个 cid 连续请求 6 次：

| 次数 | 返回内容开头 | 条数 | 是否属于该视频 |
|---|---|---|---|
| 1 | 兄弟们 | 160 | 否 |
| 2 | 那五分化呢五次把全身练一遍 | 134 | 否 |
| 3 | 今天我们要飞 1500km | 373 | 否 |
| 4 | （空） | 0 | — |
| 5 | 问大家一个问题啊…收入差距 | 330 | **是** |
| 6 | 同第 5 次 | 330 | **是** |

另一个视频（BV1CFsE6pEqp）同样是 6 次里出现 4 种内容。所以这不是个别视频，是接口整体在乱发。

**程序现在的处理**（`src/bilibili.ts` 的 `fetchBestSubtitle`）：

1. 连续取最多 **12 次**字幕，把内容相同的归为一组
2. 过滤不可用的候选（`src/subtitle.ts` 的 `subtitleUsable`）：
   - 时间戳超出视频时长太多（`max(时长+30s, 时长×1.2)`）
   - 条数 < 3 或字数 < 80（≥60 秒的视频）
   - 覆盖率 < 视频时长的 25%（例如 486 秒的视频只覆盖了 34 秒）
3. 只接受**重复出现（≥2 次）**的候选；若有多份都重复，取标题匹配分最高且唯一的那份
4. 标题匹配用二元组命中数（`titleScore`）；命中 0 时在报告「需要注意」里明确提示
5. **拿不到可信字幕就报错**，不生成报告，并提示装语音识别组件

**代价**：健康时多花约 1～2 秒（12 次轻量请求）；故障时可能直接报错。

**彻底绕开的办法**：装语音识别组件（设置页最下面，约 1.5GB），从音频转文字，完全不依赖 B站 字幕。

## 2. 多 P 视频

- 链接带 `?p=2` 才会分析第 2P，不带就是第 1P
- 报告里的时间戳链接、`打开 B站`、`重新生成` 都带 `p` 参数
- `?p` 超出实际分 P 数会直接报「该视频只有 N 个分 P」，不会静默退回第 1P
- 缓存键是 `bvid + 分P`，P1 的报告不会被当成 P2 复用

## 3. 不支持的内容

番剧、直播回放、课程（`/bangumi/`、`/live/`、`/cheese/`）会明确拒绝；视频已删除、地区限制按 B站 返回的错误码翻译成中文。

## 4. 语音识别组件依赖境外下载

- 程序从 GitHub Releases 下载 whisper.cpp，从 `hf-mirror.com` 下载模型（`huggingface.co` 在国内不通）
- 两个地址都可能超时。失败时按提示手动放文件：`.zip` 放 `downloads/`，`ggml-medium.bin` 放 `models/`，再点一次安装会跳过已存在的文件
- CUDA 版起不来时会自动回落到 CPU 版（安装包同时包含两者）
- 识别的音频文件用完即删，不在磁盘堆积

## 5. 隐私与凭据

- B站 cookie、AI key、报告都在本机 `data/app.db`，不进 git
- `GET /api/settings` 只返回掩码和登录状态，不返回 cookie
- 错误信息和日志统一用 `redactSecrets()` 过滤 `SESSDATA` / `Bearer` / `sk-` 片段
- 服务只监听 `127.0.0.1`，局域网设备访问不到

## 6. 启动脚本

`start.bat` 必须保持**纯 ASCII**：cmd 在 `chcp` 生效前按系统代码页（GBK）解析批处理，中文会拆成乱码命令。中文提示放在 `scripts/launch.ps1` 里。启动器会等 `/api/health` 返回 200 再开浏览器。

## 7. 明确没做的（记着，不是忘了）

- 段落没按句号切分（只按 300 字上限和 6 秒静音切）
- 首页没从剪贴板预填
- 超 3 小时的费用估算只显示耗时，不显示金额
- 进程崩溃后残留的 `running` 任务不会在启动时自动清理，页面会一直轮询
- `start.bat` 只用端口探测判断「已在运行」，同端口别的程序会被误认
